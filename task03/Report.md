
Це виключно різниця в індентації для тернарного оператора `:?`, у новішій версії відступ перенесених операндів зробили меншим.

## Порівняння стилю Chromium між версіями 11 і 22

Різниця доволі велика. Багато де з'явилася більш точна специфікація для вирівнювання елементів, тобто не просто булеве значення, а більше повноцінна таблиця. З'явилися цілком нові категорії вирівнювання (Align-...), (Break-...), (Indent-...). Деякі параметри переіменували. Загалом контроль над форматуванням став набагато більш детальним.


## Форматування вихідних файлів у стилі Chromium
### Версія 11

Результат `./check_format.sh` після форматування:

``` 
==== CLANG-FORMAT VERSION 11 ====
All filles are formatted well
=================================

==== CLANG-FORMAT VERSION 22.1.8 ====
All filles are formatted well
=================================

```


З різниці видно, що стиль Google відрізняється використанням двох пробілів для відступу рядка, більш С++-ною конвенцією запису вказівників (`type* var` замість `type *var`), та впорядкуванням коментарів. Також Google сортує директиви включень заголовних файлів в алфавітному порядку.

### Версія 22

Результат `./check_format.sh` після форматування:

```
==== CLANG-FORMAT VERSION 11 ====
Some files are formatted incorrectly
=================================

==== CLANG-FORMAT VERSION 22.1.8 ====
All filles are formatted well
=================================
```

При цьому `git diff -u` видає пустоту. Я підозрюю, що форматер дійсно нічого не змінив, а форматування `clang-format-11` з `chromium-11.clang-format` вже задовольняє останню версію `clang-format` з параметрами `chromium-22.clang-format`.
 Вірогідніше за все, скрипт видає помилку при перевірці `clang-format-11` якраз через те, що новіший `clang-format` має недоступні старому опції.

## Висновки

Форматер - це дуже потужний інструмент для доволі швидкого приведення коду під один стандарт. До недавнього часу я сам його недооцінював, а в деяких проєктах спеціально відключав, хоча фактично далі сам займався тим самим, просто з «костилями», як-от переганяючи код через shell-команду `column -t -o ' '` аби допасувати компонування коментарів чи декларацій змінних. Автоматизований форматер абсолютно прибирає це когнітивне навантаження, яке вбиває зайвий час.
